# Kanban Planner (Beta)

한국어 로컬 Kanban Planner입니다. 보드, 일정, 타임라인, 차트, 전체 Task 목록, Planner 휴지통, 알림과 예약 보고서를 제공합니다. 실행에 필요한 외부 패키지나 CDN은 없습니다.

## 실행

Windows, macOS, Linux에서 Node.js 24 이상이 필요합니다. GitHub에서 소스를 복제하거나 Release ZIP을 풀어 실행할 수 있습니다.

`Start-Kanban.bat`을 Windows에서 실행하거나, 앱 폴더에서 다음 명령을 실행합니다.

```powershell
node server.mjs
```

브라우저에서 <http://127.0.0.1:4197/>를 엽니다. 준비 확인은 <http://127.0.0.1:4197/api/ready>입니다. 콘솔에서 실행했다면 **Ctrl+C**, AppDash에서 실행했다면 해당 앱의 **중지** 버튼으로 종료합니다. 서버는 다른 PC에서 접속할 수 없는 루프백에 바인딩됩니다.

## AppDash에 연결

1. 앱 폴더에서 `npm run setup:appdash`를 실행합니다. 현재 앱의 실제 경로가 들어간 로컬 설정을 생성합니다.
2. AppDash의 **앱 만들기 · 연결하기**에서 `appdash-gateway-config.json`을 가져오고 작업 폴더, 유형 **service**, 실행 명령 `node server.mjs`, 포트 **4197**을 확인합니다.
3. 사용자가 직접 등록하고 앱 카드를 엽니다. 별도 토큰이나 연결을 선택할 필요는 없습니다. Teams/Outlook 주소는 Planner 설정에서 입력합니다.

이 앱은 자동 등록하거나 기존 AppDash 서버를 재시작하지 않습니다. AppDash의 기본 포트 4175와 별도 포트를 사용합니다. AppDash는 이 앱의 프로세스와 로그를 관리하고 업무 예약은 이 앱 서버 안에서 실행됩니다.

## 저장 위치와 사용법

이 **앱 폴더 자체가 단일 base**입니다.

| 위치 | 내용 |
| --- | --- |
| `public/` | 한국어 화면, 스타일, 공통 Task/필터/보고서 모델 |
| `server.mjs`, `engine.mjs`, `report-files.mjs` | 서버, 영속 저장, 실제 알림 전달, 예약 실행과 보고서 파일 |
| `data/store.json` | Planner, Task, 설정, 변경 기록, 예약 성공/대기 상태 |
| `reports/` | 한국어 예약 이력, Planner별 최신 보고서, 테스트 보고서 |
| `backups/` | 데이터 형식 변환과 전체 복원 전의 복구용 사본 |
| `test/` | Node 내장 테스트 |

처음 실행할 때 앱 폴더 안에 `data/`, `reports/`, `backups/`가 생깁니다. 저장 파일이 없으면 예제 Task 3개를 가진 기본 Planner를 생성합니다. 이후 새 Planner는 빈 Task 목록으로 시작합니다. 모든 Planner를 삭제해도 재실행 시 예제를 다시 만들지 않습니다.

## 업데이트와 데이터 이전

- **Git으로 받은 앱 폴더**에서는 앱을 종료하고 `git pull --ff-only`한 뒤 다시 실행합니다. 현재 BetaV2에 업데이트된 코드를 적용할 때도 기존 `data/store.json`을 바로 읽습니다. 저장 형식 변환이 필요하면 원본을 `backups/`에 먼저 보관합니다. 지원하지 않는 새 형식이나 손상된 저장 파일을 발견하면 원본을 보존하고 종료합니다.
- **다른 폴더에 새로 설치**했다면 새 앱의 **설정 → 데이터 백업 → JSON 가져오기**에서 이전 앱이 내보낸 백업 파일을 선택합니다. 이전 앱에 JSON 백업 기능이 없으면 앱을 종료한 뒤 이전 앱의 `data/store.json`을 선택할 수 있습니다. 보고서와 백업 폴더는 별도로 복사해 보관합니다.
- **OneDrive**에 앱 폴더를 둘 수 있습니다. 실행에 필요한 파일을 PC에 내려받고, 한 번에 한 PC에서만 앱을 실행하세요. PC를 바꿀 때는 이전 PC에서 앱을 종료한 뒤 양쪽의 동기화가 완료된 것을 확인합니다. OneDrive에 둘 때는 Release ZIP으로 설치하면 Git 관리 폴더를 동기화할 필요가 없습니다.

### JSON 백업

설정 맨 아래의 **데이터 백업**에서 현재 Planner, 다른 Planner 또는 전체 작업 공간을 선택해 저장된 목표·Task·설정·변경 기록을 내려받습니다. **Teams·Outlook 연결 주소 포함**을 선택하면 연결 주소가 평문으로 포함되므로 파일을 개인 폴더에 보관하세요. JSON 파일은 64 MiB까지 지원합니다.

**새 Planner로 추가**는 백업에서 선택한 활성 Planner를 복사합니다. **기존 Planner 하나에 복원**은 현재 데이터를 백업한 뒤 지정한 Planner를 교체합니다. 전체 백업은 **전체 복원**으로 작업 공간을 교체할 수도 있습니다. 가져온 Planner의 알림과 예약 내보내기는 꺼 두며, 기존 발송 시간과 양식은 설정에서 다시 사용할 수 있습니다. 가져온 별도 내보내기 경로는 기본 위치로 돌아가고 대기 중이던 예약은 이관하지 않습니다. 모든 Planner가 휴지통에 있거나 비어 있으면 홈에서 **데이터 백업**을 열 수 있습니다.

일반 편집은 변경한 Planner별로 저장합니다. Planner 하나의 저장 요청 한도는 12MB입니다. 가져올 때도 각 Planner의 크기를 확인합니다. 기존 작업 공간과 변경 기록은 앱 폴더의 `data/store.json`에 계속 보관합니다.

### GitHub에 배포할 파일 만들기

`npm run release -- --stage "<새 공개용 폴더의 경로>"`는 명시적으로 허용한 파일만 새 폴더에 복사합니다. 그 폴더에서 독립 Git 저장소를 준비하고 최초 커밋의 파일 목록을 확인하세요. `npm run release`는 Git을 사용해 같은 파일 목록으로 `dist/kanban-planner-v<버전>.zip`을 만듭니다. 버전 태그와 함께 이 ZIP을 배포할 수 있습니다. `data/`, `reports/`, `backups/`, 사용자 AppDash 설정 및 개인 JSON 백업은 커밋과 ZIP에서 제외합니다.

Task 상세는 **닫기, Escape, 배경 클릭, 일반 입력 Enter 제출 시 저장**합니다. 체크리스트 추가 Enter와 메모 줄바꿈은 별도로 처리합니다. 저장 중 페이지를 닫으려 하면 브라우저가 확인을 표시합니다. 저장 실패 시 입력은 화면에 남고 오류와 다시 시도를 제공합니다. 파일 쓰기는 임시 파일 작성 후 교체하며, 기존 저장 파일을 읽을 수 없으면 덮어쓰지 않고 서버 시작을 중단합니다.

Planner 삭제는 30일 휴지통으로 이동합니다. Task 삭제 및 완료 액션의 삭제는 영구 삭제입니다. 완료 액션은 미완료→완료 변경 시에만 적용하며 체크리스트 상태와 독립적입니다. Task는 카드에서 드래그하고, 체크리스트와 버킷은 핸들로 순서를 바꿀 수 있습니다. 버킷에는 위/아래 이동 버튼도 있습니다.

## 목표로 작업 묶기

Planner의 **목표 → 새 목표**에서 이름, 설명, 시작일과 기한을 설정합니다. 한 Planner에서 여러 목표를 관리하며, 각 목표 아래에 Task와 Task의 체크리스트를 둡니다. Task 상세의 **목표**에서 소속을 변경할 수 있습니다. 기존 Task는 자동으로 **목표 없음**에 표시됩니다.

목표 카드를 클릭하면 넓은 화면에서는 목표 목록 옆에 소속 Task가 표시되고, 1100px 미만에서는 전체 화면으로 열립니다. 미완료 Task는 기한순으로 나오며, 완료 Task는 필요할 때 펼쳐 볼 수 있습니다. Task 상세를 닫으면 미리보기의 목록 위치로 돌아갑니다.

- 목표 카드에서 완료 Task 수, 기한이 지난 미완료 Task 수, 다음 기한을 확인합니다. **보드 열기**는 해당 목표를 선택하며 일정·타임라인·차트·전체 목록에서도 이 필터가 유지됩니다. 화면 상단에서 목표 칩의 **×**를 눌러 해당 조건을 해제하거나 **모두 해제**로 적용된 필터를 초기화할 수 있습니다.
- **목표별 보드**는 진행 중 목표와 **목표 없음**을 접을 수 있는 행으로 표시합니다. **완료 목표 포함**을 선택하면 완료된 목표 행도 표시됩니다. **보드 열기**나 목표 필터로 완료 목표를 직접 선택하면 해당 행을 볼 수 있습니다. 각 행 안에서 카드 드래그로 버킷을 바꾸고, 다른 목표로의 이동은 Task 상세에서 합니다. **전체 보드**는 기존 방식으로 표시합니다.
- **타임라인**은 목표 일정과 하위 Task를 함께 보여 줍니다. 목표 제목을 눌러 하위 Task를 접거나 펼칩니다.
- **목표 편집 → 목표 레이블**에서 기존 레이블 하나를 선택하거나 비워 둘 수 있습니다. 선택한 레이블은 소속 Task의 표시, 필터, 알림과 보고서에 자동으로 반영됩니다. 목표를 옮기거나 레이블을 바꾸면 상속 레이블만 갱신됩니다. Task에 직접 추가한 레이블은 유지되며, 레이블을 추가해도 Task의 목표는 바뀌지 않습니다.
- 직접 기한을 입력하지 않은 Task는 소속 목표의 기한을 사용합니다. Task에 입력한 기한이 우선하며, 직접 입력한 값을 지우면 목표 기한이 다시 적용됩니다.
- 목표 카드의 **완료**를 누르면 미완료 Task에 목표 완료일을 적용합니다. **재개**를 누르면 목표 완료로 함께 완료된 Task만 미완료로 돌아갑니다. 직접 완료한 Task는 원래 완료일을 유지합니다. 목표를 삭제하면 소속 Task는 **목표 없음**에 남습니다.
- **설정 → 메시지 양식**에서 알림과 보고서에 사용할 완료 상태와 기한 조건을 정합니다. 보드 필터와 별도로 적용됩니다.

업데이트 후 이미 실행 중인 Kanban Planner는 해당 앱만 중지·시작한 다음 브라우저를 새로고침하면 새 용어가 반영됩니다. 기존 저장소를 그대로 사용합니다.

## 알림 연결 계약

Teams와 Outlook 자동 알림 및 예약 내보내기는 처음에는 모두 꺼져 있습니다. 연결 주소 입력은 가려 표시하며 외부 전송 실패 응답에 주소를 노출하지 않습니다. 주소는 `data/store.json`에 설정과 함께 저장되므로 이 폴더는 본인만 접근할 수 있는 위치에서 관리하세요. 앱은 별도 로그인·암호화 저장소를 제공하지 않습니다.

- **Teams Workflows**: HTTPS POST로 Adaptive Card 메시지(`type: message`, `attachments` 안의 `application/vnd.microsoft.card.adaptive`)를 전달합니다. Teams의 웹훅 수신 워크플로에서 이 카드를 게시하도록 구성합니다.
- **Outlook / Power Automate**: HTTPS POST JSON `{ subject, body, isHtml: true, text }`를 전달합니다. HTTP 수신 트리거의 해당 필드를 메일 보내기의 제목/HTML 본문에 연결합니다. 수신자와 라우팅은 워크플로에서 지정합니다. 본문은 사용자 텍스트를 HTML 이스케이프하고 줄바꿈과 `**강조**`를 유지합니다.
- 실제 전송은 응답이 성공 HTTP 상태일 때 수신 성공으로 기록합니다. 워크플로 수신 이후 Teams 게시나 메일 배달 완료는 외부 워크플로의 실행 이력에서 확인합니다.

Teams 연결 구성은 [Microsoft의 Workflows 웹훅 안내](https://learn.microsoft.com/ko-kr/microsoftteams/platform/webhooks-and-connectors/how-to/add-incoming-webhook)를 참고하세요. 이 앱은 별도 인증 헤더나 OAuth 로그인을 만들지 않으므로 준비한 웹훅이 이 JSON 요청을 받을 수 있어야 합니다.

미리보기는 **현재 미저장 폼**을 사용하지만 저장·전송하지 않습니다. 주소 옆의 **연결 테스트**는 현재 주소로 연결 확인 메시지만 보내고, **테스트 전송**은 설정을 저장한 뒤 선택한 시간행의 Task 알림을 실제로 보냅니다. 자동 OFF/주말에도 명시 테스트는 가능합니다. 연결 성공은 워크플로가 요청을 수신했다는 뜻입니다.

**메시지 양식**에 이름을 붙이고, 각 섹션에서 **완료 상태**와 **기한**을 선택합니다. 완료된 Task에도 기한 조건을 적용합니다. **시간별 알림 설정**에서 사용할 양식과 **요약 / 상세**를 선택합니다. 여러 시간에서 같은 양식을 사용할 수 있습니다. 요약은 Task 제목과 기한을, 상세는 목표·버킷·우선순위·완료일을 추가로 표시합니다. Teams는 섹션별 처음 3건과 나머지 건수를, Outlook은 전체 목록을 보여 줍니다. Outlook 제목과 상세 메일의 체크리스트·메모는 양식에서 지정합니다. 미리보기에서 발송 시간과 채널을 선택해 확인한 뒤 저장합니다.

이전 저장소는 전환 전에 `data/store.before-message-forms-*.json`에 백업합니다. 그대로 옮길 수 없는 조건이나 본문이 있는 시간에는 **검토 필요**가 표시됩니다. 양식과 출력 수준을 확인하고 **검토 완료 및 저장**을 누르면 해당 시간의 자동 실행을 시작합니다.

**내보내기 ON/OFF**로 예약 내보내기를 제어합니다. Planner별 **내보내기 폴더**는 Windows 파일 탐색기 선택 창에서 고르거나 절대 경로를 입력하고 저장할 수 있습니다. 비워 두면 기본 `reports` 폴더를 사용합니다. **위치 테스트**는 입력한 폴더에서 임시 파일을 생성하고 삭제합니다. **테스트 내보내기**는 현재 폴더 입력값에 `-test.txt` 보고서를 생성합니다. 두 테스트 모두 설정과 예약 기록을 변경하지 않습니다. 전체 또는 시간행의 내보내기를 끄면 대기 보고서가 보류됩니다. 다시 켜면 원래 내용으로 재시도하고, 시간행을 삭제하면 해당 대기 건을 취소합니다.

## 예약과 보고서

서버와 PC가 켜져 있어야 합니다. 약 30초마다 **PC 로컬 시각**으로 월~금의 예약을 확인합니다. 확인한 Teams·Outlook 작업은 일반 저장과 별도로 전송합니다. 앞선 전송이 느려도 확인한 다음 예약은 앱이 실행 중인 동안 대기열에서 처리합니다. 휴지통 Planner를 제외한 활성 Planner를 대상으로 하며, 앱이 꺼져 있는 동안 놓친 예약은 소급 발송하지 않습니다.

채널마다 성공 여부를 영속 기록해 성공한 채널은 같은 예약에서 다시 보내지 않습니다. 전송 실패는 해당 분 안에서 재시도합니다. 보고서 실패는 원래 내용·예약 시각을 보존한 대기열에서 이후에도 재시도합니다. 같은 이름의 기존 보고서 내용이 일치하지 않으면 오류를 표시하고 기존 파일과 최신본을 보존합니다. 운영체제가 프로세스를 강제 종료하는 순간에 외부 수신만 성공하고 로컬 성공 기록이 저장되지 않았다면 재시작 후 중복 수신 가능성은 있습니다.

예약 파일은 `YYYY-MM-DD_HH-MM-<Planner ID>.txt`, 최신은 `latest-<Planner ID>.txt`입니다. 테스트 파일에는 고유 시각과 `-test`가 붙습니다. 기존 이력은 덮어쓰지 않으며 늦게 성공한 옛 예약이 최신 파일을 과거로 돌리지 않습니다. 보고서는 재가져오기용 백업이 아닙니다. 보고서·변경 이력 자동 삭제는 없습니다.

보고서의 현재 작업은 해당 시간에 선택한 메시지 양식의 모든 섹션에서 모으며, 같은 Task는 한 번만 기록합니다. 변경 이력은 변경일을 기준으로 변경 전·후 중 하나가 양식에 해당할 때 포함합니다. 단순 수정 시각·카드 순서·미리보기 옵션 변경은 제외하며, 어제·오늘과 마지막 성공 범위 이후 누락 구간의 실제 저장 내역을 기록합니다.

테스트는 기본 데이터와 분리된 임시 폴더를 사용하고 종료 후 지웁니다. 최초 실행, 같은 폴더 업데이트, 저장·복원, 폴더 가져오기 실패와 복구, 날짜 경계, 예약과 실패 재시도, 보고서 격리를 검증합니다. 외부 전송 테스트는 합성 fetch 응답을 사용합니다. GitHub에 등록된 검증은 Windows·macOS·Linux에서 테스트와 ZIP 생성을 실행합니다.

브라우저 확인과 제한은 `docs/verification.md`에 기록합니다. 실제 Teams/Outlook 연결은 사용자가 준비한 연결로 별도 확인해야 합니다.

다른 포트로 개발 검사할 때는 `KANBAN_PORT`와 `KANBAN_TEST_INSTANCE`(영문 소문자·숫자·하이픈)를 함께 지정합니다. 예를 들어 4198 / smoke는 `data/smoke`, `reports/smoke`, `backups/smoke`를 사용합니다. 기본 앱은 4197을 사용하고, 포트를 확보한 뒤 저장소를 엽니다.
